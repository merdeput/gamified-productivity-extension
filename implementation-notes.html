Focus Garden MVP Implementation Notes

Scope Decisions

  • Implemented the MVP in the project root only. The existing focus-garden-extension folder was not modified.
  • The extension action opens a Chrome side panel. The UI file remains popup/popup.html because that folder already existed.
  • Kept the implementation in plain HTML, CSS, and JavaScript with no added libraries.
  • Refactored into a small number of medium-sized modules instead of many tiny files.
  • Moved mission, timer, reward, model, and placeholder site-list logic into state.js.
  • Centralized chrome.storage.local access in storage.js.
  • Reduced background.js to Chrome service-worker wiring and message dispatch.

Removed Screens

  • Removed the standalone Timer screen.
  • Removed the standalone Progress screen.
  • Removed the standalone Reward screen.
  • Removed the standalone Blocked Sites screen.

Final Compact UI Structure

  • Task List / Task Setup: create, select, rename, reset, and delete tasks.
  • Mission Setup + Timer: edit work/rest/session settings, start and control the timer, view session progress, see completion reward feedback, and edit placeholder blocked-site lists.
  • Garden Placeholder: shows saved seed total only.

Why Screens Were Merged

  • Timer controls belong next to mission settings because users configure and run the same mission object.
  • Progress is now compact text in the Mission area, such as Session 2 / 4, instead of a separate navigation step.
  • Reward feedback is a small notification inside the Mission area so mission completion does not redirect the user.
  • Blocked-site settings are only placeholder data, so they are collapsed inside Mission instead of taking a full screen.

Data Model

  • Tasks still own a mission object with totalSessions, currentSession, workDurationMinutes, restDurationMinutes, timerMode, remainingSeconds, and rewardClaimed.
  • Both task and mission objects store softBlockedSites and hardBlockedSites.
  • activeMission mirrors the currently running or paused mission so switching side-panel areas does not erase timer state.

Current Module Structure

  • background.js: Chrome listener setup, side-panel behavior, alarm handling, message routing, and alarm side effects.
  • storage.js: loads, normalizes, and saves extension state through chrome.storage.local.
  • state.js: pure MVP domain logic for tasks, missions, Pomodoro sessions, timer transitions, rewards, garden placeholder seed totals, and blocked-site placeholder arrays.
  • popup/popup.js: side-panel entrypoint only.
  • popup/ui.js: compact UI event handling, rendering, form payloads, message calls, and local selected-task UI state.
  • popup/popup.html and popup/popup.css: side-panel markup and styling.

Duplicate Logic Removed

  • Timer display and period calculations now come from state.js instead of being duplicated in the UI.
  • Task and mission validation now use validateTaskInput from state.js in both the background flow and UI validation.
  • Reward calculation is centralized in state.js.
  • Task/mission normalization and placeholder site-list cleanup are centralized in state.js.
  • Storage reads and writes are centralized in storage.js.

Assumptions

  • Task title editing stays in the Task area; mission timing and placeholder blocking settings stay in the Mission area.
  • Mission settings are disabled while the selected mission is actively running or paused to avoid changing timer math mid-session.
  • Final work completion completes the mission directly; no final rest is required.
  • Already-earned seeds are not removed when a mission is reset.

Timer And Session Behavior

  • idle: mission can be configured and started.
  • work: work timer is running.
  • rest: rest timer is running between work sessions.
  • paused: timer is stopped and can resume into the prior work/rest mode.
  • completed: all planned work sessions are finished and reward feedback appears in the Mission area.

Timer Drift Diagnosis And Fix

  • Diagnosis: the visible countdown is rendered in popup/ui.js, which polls the background once per second with GET_STATE.
  • Diagnosis: the timer state transition logic is centralized in state.js, especially advanceTimer, getRemainingSeconds, and getDisplaySeconds.
  • Diagnosis: the timer already stored startedAt, remainingSeconds, and timerMode, and display math used wall-clock time through Date.now().
  • Cause: while the timer was still running, advanceTimer saved the rounded whole-second remainingSeconds and reset startedAt to the current time on every poll.
  • Cause: if a poll happened before a full second elapsed, fractional elapsed time was discarded. Repeating that over many ticks made the countdown feel slower than real time.
  • Fix: running timers now keep their original remainingSeconds and startedAt baseline until pause, reset, or a work/rest transition. Each render calculates remaining time from actual elapsed wall-clock time.
  • Fix: popup/ui.js now guards against overlapping refresh calls so slow storage/message cycles cannot create stacked refreshes.
  • Result: delayed ticks should catch up on the next render instead of extending the Pomodoro.
  • No notification, sound, or new alarm feature was added for this fix.

Responsive Side Panel Layout

  • Diagnosis: the side panel CSS used a fixed body width of 410px and a fixed minimum height, so the UI did not adapt when Chrome's side panel was resized.
  • Fix: the root, body, and .app now fill the available viewport, and the active screen owns vertical scrolling. Short panels should scroll content instead of clipping it.
  • Fix: spacing, panel padding, headings, the timer, progress height, and textarea height now use clamp() where useful so the compact UI scales without becoming oversized.
  • Fix: task setup, mission duration inputs, preset buttons, and timer controls use flexible grid/flex sizing with wrapping so controls remain readable on narrow panels and spread naturally on wider panels.
  • Fix: cards, task rows, inputs, and controls use min-width: 0, overflow-wrap, and hidden horizontal overflow to avoid unwanted sideways scrolling.
  • Fix: very narrow panels stack the main tabs and row-style headers/actions using a small media query.
  • The layout remains compact and keeps the existing Tasks, Mission, and Garden screens unchanged.
  • Browser screenshot verification could not be run in this session because the in-app browser was unavailable, so validation was limited to source inspection and static checks.

Deadline Scheduling And Drag-And-Drop

  • Added deadlineDate to each task using the simple YYYY-MM-DD format.
  • New tasks default to the current local date. The date is calculated from the user's local Date object and formatted manually instead of using a hardcoded date or UTC conversion.
  • Existing saved tasks without deadlineDate are normalized to the current local date in state.js, so older task data continues to load.
  • The Task screen now renders a compact chronological board with visible date boxes for today and the next four days, plus any other dates already used by saved tasks.
  • Empty date boxes remain visible and can accept dropped tasks.
  • Task rescheduling uses browser-native drag-and-drop events: dragstart, dragover, dragleave, and drop.
  • Dropping a card sends a focused RESCHEDULE_TASK action that updates only deadlineDate, preserving all task, mission, timer, blocked-site placeholder, and reward data.
  • The existing task actions remain on each card: select/configure, rename, reset, and delete.
  • Task action buttons are hidden by default and appear only on the currently selected task card to keep the board compact.
  • A small date input was added to the task form as a fallback for creating or editing a deadline without dragging.
  • The board uses responsive CSS grid columns so date boxes stack on narrow side panels and spread naturally when there is more width.

Blocked Website Placeholders

  • The UI stores soft and hard blocked-site arrays but does not block websites.
  • The compact blocked-site section is collapsed by default using a details element.
  • Future blocking logic should connect the saved arrays in background.js to webNavigation or declarativeNetRequest.

Files Changed

  • manifest.json: configured the background service worker as an ES module.
  • background.js: slimmed down to service-worker entrypoint and message dispatch.
  • state.js: added centralized domain logic and shared helpers; fixed timer drift by preserving the running timer baseline between transitions; added task deadline normalization and rescheduling.
  • storage.js: added centralized Chrome storage wrapper.
  • popup/popup.html: collapsed navigation to Tasks, Mission, and Garden; added the task deadline date input.
  • popup/popup.html: changed the side-panel script to an ES module.
  • popup/popup.js: reduced to the side-panel entrypoint.
  • popup/ui.js: added compact UI event handling and rendering; guards against overlapping timer refresh polls; renders the deadline board and native drag-and-drop rescheduling.
  • popup/popup.css: simplified layout for the compact side-panel UI, made the side panel fluid/responsive, and added compact date-board styling.
  • implementation-notes.html: updated this documentation.

Known Limitations

  • Blocked sites are still placeholders and do not affect navigation.
  • The garden still only shows saved seeds.
  • Only one active mission is supported at a time.
  • There are no completion notifications yet.
  • There are no automated tests yet.
