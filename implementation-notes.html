Focus Garden MVP Implementation Notes

Decisions

  • Implemented the MVP in the project root and did not modify the existing focus-garden-extension folder.
  • Used popup/popup.html as the Chrome side panel UI. The folder name remains popup, but the extension action now opens the side panel instead of a popup.
  • Kept all business logic in background.js and used message passing from the UI.
  • Used chrome.storage.local for persistence because it is available in Manifest V3 and does not require a backend.
  • Used chrome.alarms as a lightweight service-worker-friendly way to check mission completion.

Assumptions

  • The MVP pipeline means task creation, mission start, timer progress, manual or automatic mission finish, reward calculation, and persisted seed total.
  • Mission durations are limited to 25, 45, and 60 minutes for this MVP.
  • Abandoned missions grant zero seeds and a reduced focus score.
  • Completed missions grant round(durationMinutes * 0.8) + 10 seeds and a focus score of 100.
  • The garden placeholder only stores and displays seeds; no flower conversion or visual garden is implemented yet.

Tradeoffs

  • The UI is plain HTML, CSS, and JavaScript to keep the project simple and loadable as an unpacked extension.
  • Timer display refreshes every second while the popup or side panel is open, while the background alarm handles completion checks at a coarser interval.
  • The UI file still lives in the existing popup folder to keep the structure simple, but it is configured as a side panel only.

Changed From Original Idea

  • Blocked-site logic is represented only by placeholder text and is not wired to web navigation.
  • The garden is represented only by persisted seed count and placeholder copy.
  • No content script is registered because the scoped MVP does not need page-level behavior.

Files Created or Modified

  • manifest.json: added Manifest V3 configuration, permissions, background service worker, extension action, and side panel path.
  • background.js: added storage initialization, task handling, mission lifecycle, timer completion checks, and reward granting.
  • background.js: configured the extension action to open the side panel on click.
  • popup/popup.html: created the multi-screen popup/side-panel UI.
  • popup/popup.css: added basic usable styling.
  • popup/popup.js: added UI rendering and message-based interactions with the background service worker.
  • implementation-notes.html: recorded implementation decisions and limitations.

Known Limitations

  • Blocked sites are not actually blocked yet.
  • The garden does not convert seeds into flowers or visuals yet.
  • There are no browser notifications when a mission completes.
  • There is no import/export, reset button, or settings screen.
  • Automatic mission completion depends on the service worker waking for alarms or UI state refresh.

Next Steps

  • Add a reset-data action for development and testing.
  • Add blocked-site rules using webNavigation or declarativeNetRequest when that part of the MVP is ready.
  • Expand the garden from seed storage into flower progress and visual feedback.
  • Add tests for reward calculation and mission state transitions.
  • Add completion notifications after the core flow is stable.
